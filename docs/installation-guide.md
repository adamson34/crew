# Installation Guide

This document covers what the CREW installer does, every config field, how placeholder stamping works, and how to reconfigure or uninstall.

For a quick-start walkthrough, see [Getting Started](getting-started.md).

## What the Installer Does

`crew/install.js` is a single Node.js script (zero dependencies) that runs 8 steps:

```
1. Collect config       ─ Interactive prompts for engagement details
2. Write .crew          ─ Engagement config file (YAML)
3. Write CLAUDE.md      ─ Engagement context for Claude Code
4. Write .crew-state    ─ Empty state skeleton
5. Create directories   ─ engagement/, assessment/, deliverables/
6. Copy crew/ module    ─ Full module (workflows, templates, data, hooks, knowledge base)
7. Stamp placeholders   ─ Replace {{placeholders}} in all .md and .yaml files
8. Register hooks       ─ Write hook config to .claude/settings.json
9. Install agents       ─ Compile and copy agent files to .claude/commands/
```

Each step is idempotent — re-running the installer overwrites previous output safely.

## Running the Installer

```bash
# From your engagement project directory:
node /path/to/CREW/crew/install.js
```

The installer must be run from the project directory where you want the engagement set up. It writes files relative to the current working directory.

## Config Fields

The installer prompts for 9 fields. All are optional — press Enter to accept defaults or leave blank.

| Field | Prompt | Default | Purpose |
|-------|--------|---------|---------|
| `firm_name` | Consulting firm name | *(blank — keeps `{{firm_name}}`)* | Stamped into SOWs, proposals, agent context |
| `user_name` | Your name | *(blank — keeps `{{user_name}}`)* | How agents address you |
| `engagement_name` | Engagement name | Directory name | Labels all outputs, artifact filenames |
| `client_name` | Client organization | `"Client"` | Used in deliverable templates |
| `vertical` | Consulting vertical | `ot-ics` | Selects domain knowledge and references |
| `assessor_skill_level` | Consultant skill level | `intermediate` | Controls guidance detail from agents |
| `engagement_artifacts` | Engagement artifacts path | `engagement` | Where SOWs, project plans, comms go |
| `assessment_artifacts` | Assessment artifacts path | `assessment` | Where findings, evidence, notes go |
| `deliverables` | Deliverables path | `deliverables` | Where reports, roadmaps go |

### Vertical Options

| Value | Label |
|-------|-------|
| `ot-ics` | OT/ICS Cybersecurity |
| `cloud-security` | Cloud Security |
| `it-audit` | IT Audit |
| `grc` | GRC — Governance, Risk & Compliance |
| `pentest` | Penetration Testing |

### Skill Level Options

| Value | Effect |
|-------|--------|
| `junior` | Agents provide step-by-step guidance, explain methodology choices |
| `intermediate` | Balanced — agents assume domain familiarity |
| `senior` | Agents defer to your expertise, focus on execution |

### Blank Fields and Placeholders

If `firm_name` or `user_name` is left blank, the `{{placeholder}}` stays in the agent files as-is. The installer warns you which placeholders remain:

```
Note: the following placeholders were left in agent files:
  {{firm_name}}
  {{user_name}}
Find and replace them manually, or re-run install.js.
```

You can re-run the installer later with the correct values, or manually find-and-replace in `.claude/commands/*.md`.

## Output Files

### `.crew` — Engagement Config

A YAML file in the project root. Read by agents and hooks at runtime.

```yaml
# CREW Engagement Configuration
# Generated by crew/install.js — edit directly to update settings.

engagement_name: "acme-assessment"
client_name: "Acme Power"
firm_name: "Meridian Security"
user_name: "Alex"
vertical: "ot-ics"
assessor_skill_level: "intermediate"

paths:
  engagement: "engagement"
  assessment: "assessment"
  deliverables: "deliverables"
```

You can edit this file directly after installation. Hooks and agents read it at runtime — changes take effect on the next session.

### `CLAUDE.md` — Engagement Context

Generated from `crew/templates/claude-md-template.md` with config values stamped in. Claude Code reads this file automatically at the start of every session, giving it:

- Engagement metadata (client, firm, vertical, lead)
- Agent command table
- Behavioral rules (check state, respect gates, update after work, artifact naming)
- Directory layout

The template contains 8 placeholders that get stamped plus `{{date}}` (auto-filled with the install date).

### `.crew-state.yaml` — State Skeleton

An empty state file with all required fields:

```yaml
crew_version: "1.0.0"
engagement: "acme-assessment"
initialized_at: "2026-02-26T10:00:00Z"

active_workflow:
  id: null
  started_at: null
  status: not_started

steps: {}

gates: {}

artifacts: []

revisions: []

completed_workflows: []
```

This skeleton passes validation. The orchestrator (`/crew IN`) populates it when you initialize a workflow. The `completed_workflows` array tracks which workflows have been finished — it's used by the orchestrator to enforce cross-workflow prerequisites and is carried forward when transitioning between workflows.

### `crew/` — Module Directory

The entire `crew/` module is copied into the engagement project so agents can reference workflows, templates, data files, and knowledge base documents at runtime. The copy includes:

```
crew/
├── agents/           # Source agent files and preamble
├── data/             # Severity scales, standards crosswalks, service catalog, engagement history
├── hooks/            # Hook scripts and validation module
├── knowledge-base/   # Domain reference docs (OT/ICS, NERC CIP, IEC 62443, NIST CSF)
├── tasks/            # Standalone task guides
├── templates/        # Deliverable templates
├── workflows/        # Workflow definitions and step files
└── install.js        # Installer (copied for re-run convenience)
```

After copying, placeholders in all `.md` and `.yaml` files are stamped with config values.

### `.claude/settings.json` — Hook Registration

The installer writes (or merges into) `.claude/settings.json` to register the 5 CREW hooks. See [Hooks Reference](hooks-reference.md) for the exact JSON structure and what each hook does.

If the file already exists, the installer:
1. Reads existing settings
2. Removes any previous CREW hooks (identified by `crew/hooks/` in the command string)
3. Adds fresh CREW hooks
4. Preserves all non-CREW settings

If the file is invalid JSON, it backs up the original to `.claude/settings.json.bak` and starts fresh.

### `.claude/commands/` — Agent Slash Commands

Seven agent files are installed as Claude Code slash commands:

| File | Command | Notes |
|------|---------|-------|
| `bd.md` | `/bd` | Preamble injected, placeholders stamped |
| `pm.md` | `/pm` | Preamble injected, placeholders stamped |
| `consultant.md` | `/consultant` | Preamble injected, placeholders stamped |
| `compliance.md` | `/compliance` | Preamble injected, placeholders stamped |
| `writer.md` | `/writer` | Preamble injected, placeholders stamped |
| `reviewer.md` | `/reviewer` | Preamble injected, placeholders stamped |
| `crew.md` | `/crew` | Orchestrator — NO preamble (it manages state, doesn't follow it) |

### Artifact Directories

Three directories are created if they don't already exist:

- `engagement/` — SOWs, project plans, communications
- `assessment/` — Findings, evidence, analysis notes
- `deliverables/` — Reports, roadmaps, presentations

Paths are configurable via the `engagement_artifacts`, `assessment_artifacts`, and `deliverables` config fields.

## Placeholder Stamping

After copying the `crew/` module, the installer walks every `.md` and `.yaml` file and replaces `{{placeholder}}` tokens with config values.

### Supported Placeholders

| Placeholder | Source |
|-------------|--------|
| `{{firm_name}}` | Config field |
| `{{user_name}}` | Config field |
| `{{engagement_name}}` | Config field |
| `{{client_name}}` | Config field |
| `{{vertical}}` | Config field |
| `{{assessor_skill_level}}` | Config field |
| `{{engagement_artifacts}}` | Config field (default: `engagement`) |
| `{{assessment_artifacts}}` | Config field (default: `assessment`) |
| `{{deliverables}}` | Config field (default: `deliverables`) |
| `{{date}}` | Auto-filled: install date (YYYY-MM-DD) |

### Where Placeholders Appear

- **Agent files** — Agent identity sections, workflow references
- **Workflow step files** — Artifact paths, client references
- **Workflow YAMLs** — `produces` and `required_artifacts` path patterns
- **Templates** — Document headers, client/firm names
- **CLAUDE.md** — Engagement metadata, directory layout

If a config field is `null` (left blank), the `{{placeholder}}` stays in the file for manual replacement.

## Preamble Injection

The installer reads `crew/agents/preamble.md` and prepends it to every role agent (bd, pm, consultant, compliance, writer, reviewer). The orchestrator (`crew.md`) does NOT get the preamble — it manages state rather than following it.

Injection point: after the first `# ` heading line in each agent file. This keeps the agent's title as the first line, followed by the state protocol, followed by the agent's persona content.

See [Architecture](architecture.md) for details on the preamble protocol.

## Reconfiguring

Re-run the installer from the engagement directory:

```bash
node crew/install.js
```

This overwrites `.crew`, `CLAUDE.md`, `.crew-state.yaml`, re-copies and re-stamps `crew/`, re-registers hooks, and re-installs agents. It does NOT delete existing artifacts in `engagement/`, `assessment/`, or `deliverables/`.

**Warning:** Re-running the installer resets `.crew-state.yaml` to an empty skeleton. If you have workflow progress, back up the state file first.

## Uninstalling

```bash
node crew/install.js --uninstall
```

Removes:
- All 7 agent slash commands from `.claude/commands/`
- `.crew` config file
- `.crew-state.yaml` state file
- `CLAUDE.md`
- CREW hooks from `.claude/settings.json` (preserves non-CREW settings; deletes the file if empty)
- `crew/` module directory

Does NOT remove:
- `engagement/`, `assessment/`, `deliverables/` directories (your work stays)
- Any other files you created
